# SGT v0.8.7 — численная сверка SGP4

Эти проверки **не требуются для запуска приложения** и не меняют его данные.
Они нужны для сравнения положения спутника с независимой реализацией SGP4.

## 1. Проверка геометрии и метода прогноза без интернета

После установки Node.js 22.16+ откройте `frontend/test-orbits.cmd`.
Восемь тестов проверяют преобразование TEME в координаты Cesium для LEO/MEO/GEO,
различие между пространственной орбитой и наземной траекторией GEO, отсечение
некорректных чисел, уточнение AOS/LOS и максимум TCA на синтетических данных, включая реальный SGP4 для WGS F9 по историческим OMM.

Это НЕ самостоятельная проверка качества каталога CelesTrak или работающего WebGL.

## 2. Сравнение реальных координат по двум независимым библиотекам

После первого запуска `setup.cmd`/`dev.cmd` и загрузки каталога CelesTrak:

```powershell
cd frontend
node scripts/sgp4-audit.mjs
python -m pip install sgp4
python ../scripts/compare_sgp4.py sgp4-audit-output.json
```

Node использует `satellite.js`, Python — `python-sgp4` и **те же OMM**,
производит расчёты в TEME **в те же моменты UTC**. Отчёт включает МКС,
GPS/MEO и GEO (предпочтительно WGS F9, если есть в загруженном каталоге).
Если нужный класс отсутствует, появится предупреждение.

Отчёт `sgp4-audit-output.json` можно сохранить как доказательство QA.
Учитывай возраст OMM: совпадение двух библиотек не гарантирует, что
расчёт совпадёт с фактическим положением при устаревших элементах.

## 3. Прогнозы AOS / TCA / LOS

Синтетические тесты методов уточнения находятся в `frontend/tests`.
Для настоящего независимого сравнения пролётов необходимо взять одинаковые
OMM, UTC, координаты/высоту наблюдателя, маску возвышения, горизонт 60 мин и
сравнить с отдельным инструментом (например, Skyfield либо собственным
reference pipeline на `python-sgp4`): времена AOS / TCA / LOS и углы места.
Существующий pass worker использует 60-секундный coarse scan, binary crossing
и peak search; здесь **алгоритм не изменялся**. При коротких пролётах он
теоретически может пропустить событие между точками coarse scan, поэтому
полную точность прогноза до независимой сверки не заявляем.

## 4. Проверка в браузере перед выпуском

- GEO WGS F9: линия теперь представляет полноценную 3D-орбиту за пределами Земли,
  а не маленькую петлю ground track на её фоне.
- МКС и GPS: маркер находится на орбите, нет провала линии сквозь Землю.
- После 2–5 минут слежения орбита остаётся согласованной с маркером.
- Кнопки MAP / SDR / PASSES, FOV Ctrl+Wheel, станция наблюдения — без регрессий.
- Сверить несколько полноценных пролётов на одних OMM/UTC/масках.

## 3a. Независимый справочник пролётов из Python

После установки необязательной зависимости `python -m pip install sgp4`:

```powershell
python scripts/reference_passes.py --lat 61.254 --lon 73.396 --height 0 --mask 10 --minutes 60 --norad 25544
```

Параметры `--lat` и `--lon` — **пример**, их следует заменить координатами
реального наблюдателя в SGT. При необходимости можно повторить `--norad`.
Для точного сопоставления начала временного окна используй `--start` с ISO
UTC, например `--start 2026-11-03T19:00:00Z`. Сравни те же OMM, высоту,
временное окно, маску и спутник в SGT.

В отличие от рабочего SGT, reference-script уточняет события на 10-секундной
сетке, используя python-sgp4, другую реализацию GMST и golden-section peak
search. Скрипт не заменяет фактическую проверку трекинга на живом небе.
